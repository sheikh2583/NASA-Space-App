## Goal
Produce an honest final assessment and submission claim audit; 9/10 is an ambition, not a completion checkbox.

## Steps
1. Read final source/runtime evidence, all scientific dispositions, actual user observations, device/capacity reports, corroboration disposition and final presentation assets.
2. Trace every challenge-contract C/Q row and headline numerical claim to the verified release dossier. Remove/qualify incompatible or unsupported claims.
3. Seek fresh technical/practitioner scrutiny where Sheikh supplies it; disclose reviewer contribution/proxy status. Do not invent an independent reviewer.
4. Rehearse the scientific questions and the timed demo. Record actual timing and audience comprehension.
5. Score Impact/Creativity/Validity/Relevance/Presentation using the original anchors, with evidence and caveats. No official weights/award odds are invented.
6. Create final assessment and limitations submission text. Explicitly retain deductions for unresolved conditional uncertainty, limited support or missing user/external evidence even if code is complete.

## Acceptance
- [ ] A dated, sourced reassessment explains each score and every deferred/failed gate.
- [ ] Limitations match the actual live runtime and submission wording.
- [ ] A lower score remains an acceptable honest outcome; no automatic promotion to 9.

## Stop and ask if
A final claim contradicts evidence or submission format rules remain unresolved. Report it before submission; do not rewrite history.
